# Slides · 小红书小工具版

这一版**自成一个目录**，和另外两版完全分开保存：

| 版本 | 源码 | 产物 | 谁在跑 |
| --- | --- | --- | --- |
| 网页版 | `src/` + `index.html` + `vite.config.ts` | Vercel | play-slides.com |
| 微信小游戏 | `wxgame/` | `wxgame/game.js` | 微信（暂停中） |
| **小红书小工具** | **`xhs/`（本目录）** | **`xhs/dist/` + zip** | 小红书笔记里的小工具 |

改这一版**不会动到**网页版的 `src/style.css`、`index.html`、`vite.config.ts`，
也不会动 `wxgame/`。反过来也一样。

## 但玩法规则是共用的，不是抄的

`xhs/src/` 里只有这一版**自己**的东西：入口、主菜单、本机记录、介绍页、
Chrome 61 基线样式、打包配置。**棋盘、规则、手感、动画、结算、战绩图全部
从 `src/` 引用**（`createSquareGame` / `createCircleGame` / `engine/*`），
一行都不复制。

理由是玩家定的那一条：选出来的玩法要「完全复刻一样」。抄一份的话，网页版
以后改一次规则，这边就落后一次——微信那版是抄的，已经开始对不齐了。引用是
只读的：小红书这一版从不修改 `src/` 里的任何文件。

五个玩法就是网页版同一个入口的五组开关（`ShapeGameOpts`）：

| 玩法 | 怎么开 |
| --- | --- |
| 基础方块 | `createSquareGame().mount(el, back, {})` |
| 基础小球 | `createCircleGame().mount(el, back, {})` |
| 炸弹 | `{ bomb: true }` |
| 老虎机 | `{ targets: [老虎机转出来的两个图案] }` |
| 无限反转 | `{ flip: true }` |

## 和网页版不一样的三处（玩家点头的）

1. **没有排行榜**——小工具不联网。改成**本机游玩历史**（localStorage）。
2. **没有登录 / 订阅 / 天才**——五个玩法全部免费打开。
3. **分享战绩图**改走小红书的 JSBridge：存相册、发笔记。网页版那条「长按
   保存」在这儿行不通（长按菜单被容器禁掉了）。

多人小屋整块不做。

## 教学是两层，都是网页版的原件

**第一层：分镜动画，没有一个字。** 第一次点开《经典方块》放方块那一段，第一次
点开《经典小球》放小球那一段，各放一次，看过就记住。用的是网页版那两个原件
（`src/ui/tutorial.ts`、`src/ui/circleTutorial.ts`），连播放速度都是它自带的
（`storyTutorial.ts` 里的 `SPEED = 2.25`）；下面那四颗键（上一条 / 再一次 /
下一条 / 完成）也是原件自带的，这一版不加不减不改。

炸弹、老虎机、无限反转**不放**——那三个是在基础玩法上加一层规则，玩到那儿的人
已经会滑了。判断条件和网页版一字不差（见 `main.ts` 的 `storyFamilyFor`）。

**第二层：六条规则，有字有配图。** 不会自己跳出来，两个入口都得玩家自己按：
成绩与说明页上一颗《怎么玩》，局中按暂停面板里一颗。前面先看一段纯动画，还有
疑问的人自己到这两处来看字。

`npm run check:story` 专门守这一套：该弹的弹、不该弹的不弹、弹过一次不再弹。

另有三处更小的、想清楚了才留的差别，跑体检时会一条条念出来（见下一节）：

* **主菜单上炸弹那张卡的图**。网页版那张画的是**整块炸弹板块**（基础 / 90 秒
  / 进阶三档的缩略图），因为点开它是要挑档次的。这一版只有基础一档，摆一张
  三档的缩略图是在说假话，所以换成网页版自己的「这一局是炸弹局」标志
  （`homeIcons.ts` 的 `ICON_BOMB_BADGE`，网页版把它摆在炸弹局的开局页和战绩
  图上）。`check-vsweb.mjs` 有一屏专门证明这两张是同一张。
* **老虎机挑形状那一屏少一颗三角**。三角整块不做。留下的两颗和网页版逐字节
  相同。
* **暂停面板多一颗《怎么玩》**。网页版那六条规则在教学挑选页上，这一版没有
  那一页，所以入口挪进暂停面板（另一处在成绩与说明页）。

还有一处不在画面上：**主菜单五张卡的读屏名**（`aria-label`）跟着卡底下那行
小字走，网页版跟着玩法的正式名字走（「方块」而不是「经典方块」）。这一版一屏
只有五张卡，看得见的字和听得见的字对不上没有好处；「基础炸弹」那个名字还会
主动误导——「基础」是相对于 90 秒和进阶说的，那两档这一版没有。看得见的那行
小字仍旧和网页版逐字相同，走的是同一张表（`menuTags.ts`）。

## 五道门

```
npm run check:xhs:all  # 全跑一遍，提审前用这个
```

拆开是五台：

```
npm run check:xhs      # 老内核那两台：删掉 Chrome 61 没有的 19 处接口跑五个
                       # 玩法；再强制走样式降级层，逐个盒子比坐标和尺寸
npm run check:vsweb    # 逐屏对着网页版核内容
npm run check:story    # 分镜动画教学：该弹的弹、不该弹的不弹、弹过不再弹
npm run check:submit   # 提审前自查：把 zip-artifact-spec.md §6 那张清单跑一遍
```

另有一道不用单独跑——**语法门禁**在 `npm run build:xhs` 里，出包时自动过：
拿只认 ES2017 的解析器把拼好的整份产物读一遍，读不下来就不出包。这一关是别处
补不上的：上面那两台老内核体检台跑在**新** Chromium 上，删得掉接口，删不掉
「这个浏览器认识 `?.`」——包里混进一个可选链，它们照样全绿，真机上却是解析阶段
就死，白屏，而且一条报错都留不下。

`check:vsweb` 起一个本地服务器把网页版的 `dist/` 跑起来，再把这一版的
`preview.html` 跑起来，同一个玩法两边各开一局，把看得见的东西抓下来对：得分
图案、三个读数的名字、底排两颗键的图标和读屏名、标题副标题、开局页、暂停面
板、结算页、成绩栏、六条规则，横竖屏各一遍。分数和随机发牌两边不可能一样，
所以数字统一换成 `#`。

上面那三处说好的差别写在脚本里、每次都跑——哪天网页版改了别处，或者这一版
不小心多漏了一样，它立刻从「说好的」里掉出来变成没过。

`check:submit` 读的是**真正要传上去的那个 zip**，不是 `dist/`：包结构、文件
类型、`index.html` 的每一条硬性要求、脚本里的禁用写法、体积，最后把解压出来的
包用 `file://` 真的跑一局（主菜单 → 开局 → 拖八下 → 结算 → 画战绩图 → 成绩页
→ 战绩详情），盯着浏览器发出的**每一条请求**——只许 `file:` 和 `data:`，出现
别的就是没过。「不联网」这一条静态扫描证明不了，只有跑起来看得见。

## 怎么打包

```
npm run build:xhs
```

出来的是 `xhs/dist/`（`index.html` 在根）和一个可以直接传进 Builder Hub 的
`xhs/slides-minitool.zip`。

`dist/` 不进仓库（根 `.gitignore` 里 `dist` 那条），**但 zip 进**——这是故意
的：玩家那台电脑上没有 Node，跑不了 `npm run build:xhs`，只能从 GitHub 网页
上把 zip 下下来传进 Builder Hub。直链：

<https://github.com/MACHOGGG/Cube/raw/refs/heads/claude/fangtang-game-web-app-xbecza/xhs/slides-minitool.zip>

所以每次改完这一版，**都要重新 `npm run build:xhs` 再提交那个 zip**，否则玩
家下到的还是上一版。

规范和限制见 `.claude/skills/minitool-zip-builder/`（小红书官方那份技能包）。
